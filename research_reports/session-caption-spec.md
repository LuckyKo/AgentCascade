# SPEC: Session caption (compression-derived, shown in UI)

**Goal:** Give each agent session log a short human-readable **caption** so that many same-named sessions (e.g. dozens of `orchestrator_Maine_*`) can be told apart at a glance instead of by file size/mtime. Caption is generated by the compressor, stored in the log's line-1 metadata, and shown under the agent name in the UI session list (read-only).

**Scope decision (user-confirmed):**
- Compression-only: short sessions that never compress get **no caption** (fine — same as today).
- **No manual edit** in v1. If a user wants to change one, they edit the JSONL line 1 directly.
- Caption is read from the log metadata when the session list loads/refreshes.

---

## Data flow (end to end)

```
compressor LLM emits:  <summary>\n--- END SUMMARY --- CAPTION: <one-line text>
        │
        ▼  agent_invoker.py (invoke_compression_agent)
   validate + PARSE caption out of the tail, strip whole `--- END SUMMARY ---...` from summary body
        │  returns (summary, caption)
        ▼  core.py (~555) → build_marker_message(summary, fraction)   [marker body stays clean, NO caption in it]
        │
        ▼  logger: set metadata["caption"] = caption  (only if not already set → first meaningful caption wins)
        │  persisted via the existing compression rewrite path (no new rewrite mechanism needed)
        ▼
   /api/sessions reads line-1 metadata → returns "caption"
        ▼
   UI renderSessions() shows caption under the agent name (read-only)
```

**Key invariant:** the caption must NEVER appear inside the `<context_summary>` marker body that goes back into the model context. It is parsed out and stored only in metadata.

## Change 2 — Parse + strip (THE delicate part)

**File:** `agent_cascade/compression/agent_invoker.py`, function `invoke_compression_agent`, block at lines ~345-379.

Current behavior:
- Requires `summary.strip().endswith(COMPRESSION_END_MARKER)` (line 369) — **this will now fail** if a caption follows the marker. Must be updated.
- Strips the marker: `summary = summary[:-len(COMPRESSION_END_MARKER)].strip()` (line 377).
- Returns only `summary` (line 379).

New behavior (must be robust — do NOT corrupt the summary or break retry validation):
1. Take the raw stripped text. Find the LAST occurrence of `COMPRESSION_END_MARKER`.
2. Validate that everything **before** that marker is non-empty (the actual summary). If not → raise the existing "empty summary" error.
3. Everything **after** the marker is the optional caption region:
   - Expected form: ` CAPTION: <text>` (space then literal `CAPTION:` then a single line of text).
   - Parse with a tolerant regex anchored to the marker, e.g. match `(?:^|\n)\s*--- END SUMMARY ---\s*(?:CAPTION:\s*(?P<caption>[^\n]*))?\s*$` against the stripped text. 
   - If a `CAPTION:` line is present and non-empty → `caption = <text>.strip()`. Otherwise `caption = ""`.
   - **If the region after the marker is present but does NOT match `CAPTION: ...`** (e.g. stray text), treat it as malformed: log a warning, set `caption = ""`, and do NOT let stray text leak into the summary. The summary body is everything before the marker regardless.
4. Summary body = text **before** the last marker, stripped. This replaces the old `[ :-len(MARKER) ]` slice and is safe whether or not a caption was present.
5. **Backward compatibility:** if there is NO `CAPTION:` (old behavior / model omits it), `caption=""` and summary body is identical to today's result. Existing tests that assert the end-marker validation must still pass.
6. Return `(summary, caption)` — a 2-tuple. **Update ALL callers** of `invoke_compression_agent` (see Change 3) to unpack both.

Add unit tests for: caption present; caption absent (old format); empty summary with marker; malformed trailing text after marker; caption containing the marker string itself (edge); multi-line caption must be rejected/trimmed to first line.

## Change 3 — Thread caption into metadata (no new rewrite mechanism)

**Files:** `agent_cascade/compression/core.py` (~533-558), `agent_cascade/logger/agent_instance_logger.py`.

1. Where the summary is consumed and the marker built (`core.py:~555`, `build_marker_message(generated_summary, fraction)`): now also receive `caption`. The marker message itself is unchanged (no caption in body).
2. Persist to metadata: set the instance logger's in-memory metadata so that a subsequent rewrite persists it:
   - Add a small method on `AgentInstanceLogger`, e.g. `set_caption(caption: str)` (mirror `update_supervisor` at agent_instance_logger.py:108-115): sets `self.data["metadata"]["caption"] = caption` **only if** `"caption"` is not already present/non-empty (first meaningful caption wins; do not clobber an earlier or user-edited value). In-memory only, like `update_supervisor`.
   - The existing compression rewrite path (`_sync_marker_single_write` at agent_instance_logger.py:665, and/or `rewrite_log_with_history` at :553) already re-emits the metadata header line — so once `set_caption` has updated in-memory metadata, the next such rewrite persists it to disk. **Confirm during implementation** that the compression flow actually triggers one of these rewrites after the marker is inserted (it should, since it syncs the marker). If not, ensure the caption rides along on whichever write already happens for the marker — do NOT add a separate full-file rewrite just for the caption.
3. Add `"caption": ""` (or omit) to the metadata dict default at agent_instance_logger.py:78-89 so the field is well-defined. Omitting when empty is fine; ensure readers tolerate its absence.

## Change 4 — Surface in API + UI (read-only)

**File:** `agent_cascade/api_server.py`, `/api/sessions` endpoint (lines ~893-931).
- Currently builds each entry from the filename only. Add: read **line 1** of each `.jsonl` (cheap — open, read first line, `json.loads`, grab `metadata.get("caption","")`) and include `"caption"` in the returned dict (lines ~917-924). Guard against malformed/empty files (skip caption → ""). Only read line 1 for the caption.
- **Fallback when caption is empty:** if `caption` is absent/empty, derive a display fallback from the **first USER message** in the log: scan forward from line 2 to the first message with `role == "user"` (reuse the same role constant as `session_io.py`), take its text content, and **truncate to ~120 chars** (append `…` if cut) — a first user message can be a long prompt or pasted file, so never return it raw. Put this in the SAME `"caption"` field (so the UI needs no separate field/logic); the value is simply "real caption if present, else truncated first-user-message, else ""." Only read as many leading lines as needed to find the first user message (stop early; do not read the whole file).
- Net: `caption` field semantics = `metadata.caption` if set, else `truncate(first_user_message, 120)`, else `""`.

**File:** `web_ui/app.js`, `renderSessions()` (lines ~958-969).
- Add a caption row under the agent name, e.g. after the `session-item-agent` span: render `<span class="session-item-caption">…</span>` with `s.caption` (escape via existing `escapeHtml`). Because of the API fallback, `s.caption` is now populated for almost every session (real caption, else truncated first-user-message); only omit the row when it is truly empty. Add minimal CSS for `.session-item-caption` (muted, smaller font) consistent with existing session-item styling.
- Read-only: no edit control in v1.

## Testing requirements
- **Unit (compression parse):** the 6 cases listed in Change 2. These are the critical ones — the parser must not corrupt summaries or break the end-marker validation/retry path.
- **Unit (metadata):** `set_caption` sets-once semantics (second call does not overwrite); absent field tolerated by readers.
- **Unit (API):** `/api/sessions` returns the real caption from a temp JSONL whose metadata has `caption`; when metadata caption is empty it falls back to the truncated first USER message; returns "" only when there's neither. Verify truncation caps long first-user messages at ~120 chars with an ellipsis, and that it stops reading early (does not parse the whole file).
- **Existing regression:** run the existing compression test suite — end-marker validation, retry logic, and marker-building tests must still pass unchanged in behavior when no caption is present.

## Non-goals (v1)
- No manual caption editing UI/endpoint.
- No caption for non-compressed sessions.
- No changes to how the model sees context (caption stays out of the summary body).
- No SQLite/index work.
